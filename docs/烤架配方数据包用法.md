# 烤架配方数据包用法

2026-10-13：1.21.1 NeoForge 与 1.20.1 Forge 均已接入原版 RecipeManager，配方类型和序列化器 ID 均为 `northeast_china_delight:grill`。这是服务端数据包功能，不是客户端贴图资源包功能；服务端会把加载后的配方同步给客户端和 JEI。

## 文件路径与稳定 ID

- 1.21.1：`data/<命名空间>/recipe/<配方路径>.json`。
- 1.20.1：`data/<命名空间>/recipes/<配方路径>.json`。
- ID 是 `<命名空间>:<配方路径>`，不含目录 `recipe(s)` 和后缀 `.json`。
- 覆盖内置规则时使用同一命名空间、同一路径；新增规则使用新路径或自定义命名空间。
- 1.20.1 的通用标签使用 `forge:`，1.21.1 使用 `c:`；模组内置 JSON 在构建时自动转换，但自己制作的数据包须使用目标版本的标签。

数据包根目录还须有符合当前游戏版本的 `pack.mcmeta`。将整个数据包文件夹或根目录含该文件的 ZIP 放到对应世界的 `datapacks/` 目录，通过 `/datapack list enabled` 确认已启用，再执行 `/reload`；不要只把 JSON 文件复制到客户端资源包目录。

| 内置配方 ID | 菜肴 | 时长 | 调料份数 |
| --- | --- | --- | --- |
| `northeast_china_delight:grill/grilled_chicken_frame` | 烤鸡架 | 20 秒 | 2 |
| `northeast_china_delight:grill/grilled_corn` | 烤玉米 | 20 秒 | 1 |
| `northeast_china_delight:grill/grilled_oil_edge` | 烤油边 | 25 秒 | 2 |
| `northeast_china_delight:grill/grilled_cold_noodles` | 烤冷面 | 30 秒 | 4 |

源文件位于 `src/main/resources/data/northeast_china_delight/recipe/grill/`。以上食材、调料和时长保持迁移前的内容。

## 覆盖烤冷面示例

1.21.1 放在数据包的 `data/northeast_china_delight/recipe/grill/grilled_cold_noodles.json`，1.20.1 改用 `recipes/` 并把以下 `c:` 改为 `forge:`。

```json
{
  "type": "northeast_china_delight:grill",
  "config": {
    "priority": 0,
    "input": {"item": "northeast_china_delight:cold_noodle_sheet"},
    "seasonings": [
      {"tag": "c:foods/seasonings/chili_sauce"},
      {"tag": "c:eggs"},
      {"tag": "c:sugar"},
      {"tag": "c:foods/seasonings/vinegar"}
    ],
    "result": {"item": "northeast_china_delight:grilled_cold_noodles", "count": 1},
    "seconds": 30
  }
}
```

禁用同一条配方时，覆盖为下面的完整文件即可，不需要继续保留食材或产物字段：

```json
{"type":"northeast_china_delight:grill","config":{"disabled":true}}
```

在一个数据包中删除覆盖文件，只会让较低优先级数据包或模组的原配方重新生效；要停用模组自带的规则，应同 ID 覆盖并设 `disabled`。

## 字段约定

| `config` 字段 | 含义 |
| --- | --- |
| `disabled` | 可选布尔值，默认 `false`；为 `true` 时不提供规则，且 JEI 不显示它。 |
| `priority` | 可选 32 位整数，默认 `0`；同食材的多条规则先按该值降序，再按完整配方 ID 字符串升序匹配。 |
| `input` | 必填的标准 Ingredient，支持 `{"item":"物品 ID"}`、`{"tag":"标签 ID"}` 或任选数组；每次烤制使用一件食材。 |
| `seasonings` | 可选数组，默认 `[]`，最多四个条目；每个条目是一份 Ingredient，可以是物品、标签或任选数组。重复条目代表额外剂量，不合并份数。 |
| `result.item` | 必填的已注册物品 ID，不能是空气。 |
| `result.count` | 可选正整数，默认 `1`，不超过成品物品的堆叠上限。 |
| `seconds` | 必填正整数，表示烤制秒数；乘以 20 后必须仍在 32 位整数范围内。 |

例如同一调料格允许盐或糖，可以使用 `[{"item":"northeast_china_delight:salt"},{"item":"minecraft:sugar"}]`；把该数组放在 `seasonings` 的一个元素中，表示“任选一种”，不是两份调料。不同条目可能重叠，每件已加调料最多满足一个条目，匹配不受添加顺序影响。

瓶装调料保留现有刷料规则：主手刷子、副手调料瓶，每个条目消耗 10 mB；辣椒酱等酱料消耗一份，盐、糖、鸡蛋等普通物品消耗一件。数据包只改变需要哪些条目，不改变这些交互动作。

紧凑格式的 `config` 超过 32767 字符时拒绝加载，避免配方同步失败；大量任选食材请用标签。非法食材、空 Ingredient、超过四份调料、非法产物数量或时长也会在加载阶段拒绝，并写出配方解码错误。

## 重载、存档与 JEI

- 把数据包安装到世界，执行 `/reload`；客户端普通资源包列表不能替代这一步。
- 架上每份食材都保存配方 ID，NBT 的 `GrillRecipes` 列表与四个食材槽一一对应。
- 同 ID 的规则被重载替换后从零重新计时；仍能匹配新规则的调料会保留，多余或不适用的条目被清除。
- 已绑定的 ID 被禁用、删除，或新输入不再匹配当前食材时停止加工。即使尚未计时或没有加过调料，也不会切换到其他同食材规则；原料可空手右键取回后重新放入。
- 配方恢复后继续使用原 ID，并从零计时。各食材槽位独立绑定和暂停。
- 无 ID 的旧烤架存档在第一次解析时按当前食材、优先级和 ID 排序绑定，保留兼容的调料与旧进度。
- JEI 从同一份服务端配方列表生成页面，稳定 ID 与加工规则一致；一条规则一页，食材和每种调料的标签候选在各自槽位内滚动，不拆成重复配方。

## 实现与回归入口

- 注册、JSON 校验和双版本网络序列化：`crafting/ModGrillRecipes.java`、`GrillDataRecipe.java`。
- 世界配方查询、确定性排序及逐份调料匹配：`crafting/GrillRecipes.java`。
- 每槽绑定、重载暂停及旧存档迁移：`block/GrillBlockEntity.java`。
- 放料、刷料和实体烤制：`block/GrillCampfireBlock.java`。
- JEI 页面与配方更新：`compat/jei/GrillJeiRecipes.java`、`GrillRecipeCategory.java`、`NortheastJeiPlugin.java`、`VatJeiSync.java`。
- 回归：`gametest/GrillGameTests.java`，共 11 项，覆盖默认配方、稳定 ID、覆盖/禁用/新增、优先级、重复与重叠调料、重载、零进度绑定、存档、网络、非法 JSON、独立槽位和实际实体掉落。
