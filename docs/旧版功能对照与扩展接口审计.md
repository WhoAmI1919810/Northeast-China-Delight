# 旧版功能对照与 CRCI 扩展接口审计（2026-11-12）

## 结论

新东北乐事与 CRCI 的组合已经覆盖旧东北乐事的现有内容与主要行为，两个版本都可以独立构建、加载并运行全量 GameTest。

CRCI 已经具备后续地区乐事所需的主要接入面：通用内容启用、气候农田池、五类默认职业交易、任意已注册职业交易、地区专属交易注入、副食店开关、客户端可用性同步和数据包档案。普通地区乐事不需要修改 CRCI 的农田生成器或交易类，只需要提供自己的内容、配方、档案和必要的世界生成数据。

本轮审计补齐了一个实际缺口：钓鱼战利品和猪副产物掉落此前没有经过 CRCI 启用集合判断。现在两者统一使用 `CrciAvailability.isContentEnabled(Item)`，不会再让未来地区已禁用的食材从这两条自然获取途径漏出；该入口不受箱子开关影响，保持原有配置语义。

## CRCI 扩展契约

### 地区档案

路径：`data/<地区命名空间>/crci/profile.json`，当前 `schema` 为 `1`。

- `owner` 必须等于档案命名空间，且对应模组已加载。
- `enabled_content` 用于启用 CRCI 中可启用的食材、种子、箱袋和加工原料，也可以列出本地区自己的物品；多个已安装地区的启用集取并集。
- CRCI 的工具、机器和容器属于基础内容，不允许由地区档案禁用或启用。
- `farm_crops` 的 `seed` 必须已启用；`full_growth` 使用标准 `Name`/`Properties` 方块状态；`pools` 指定气候池和权重。
- `trades` 支持 `farmer`、`wanderer`、`side_dish`、`butcher`、`fisherman` 旧别名，也支持 `namespace:profession` 完整职业 ID。
- 未带命名空间的未来职业键会落到档案 owner 命名空间，例如 `futuremod:future_herbalist`。
- `trade_overrides` 可按交易 ID 调整等级、最大次数、经验和价格倍率。
- `side_dish_shop` 控制是否允许加载 CRCI 的副食店结构包。

### 运行时查询

- `CrciAvailability.isAvailable(Item, CrciUseSite)`：用于农田、交易、箱子、创造栏、JEI、配方书和世界生成等有获取开关的入口。
- `CrciAvailability.isContentEnabled(Item)`：只判断内容是否在当前启用集内，不受农田、箱子或交易开关影响；适合钓鱼、实体副产物、植物自然掉落等自然获取入口。
- 非 CRCI 物品按所属模组是否加载判断；原版和其他模组不会因 CRCI 的地区档案被误隐藏。
- 客户端会在服务端档案快照变化后重建创造栏和配方书集合。

### 副食店与职业

- 副食店结构与副食商职业均由 CRCI 提供；没有地区档案请求 `side_dish_shop` 时不加载副食店数据包，也不生成可认领的副食商工作站。
- 有 Create 时加载 Create 版副食店结构包，否则加载普通版；两套互斥。
- 同一村庄结构只允许放置一座副食店，唯一性由 `UniqueShopPoolElement` 保证。
- 副食商交易池可以同时包含多个地区的内容；未启用地区的物品不会进入报价。

## 自然获取途径审计

| 途径 | 当前守卫 |
|---|---|
| 村庄农田 | `RegionalFarmCropProcessor` + `CrciUseSite.FARM` |
| 箱子战利品 | Northeast 箱子配置 + `CrciUseSite.LOOT` |
| 村民交易 | 地区档案 + `CrciUseSite.TRADE` |
| 钓鱼 | `CrciAvailability.isContentEnabled` |
| 猪副产物 | `CrciAvailability.isContentEnabled` |
| 野生作物与植物 | 各 worldgen feature 的 `CrciUseSite.WORLDGEN` |
| 创造栏、JEI、配方书、ALI | `CREATIVE` / `JEI` / `RECIPE` 可用性查询 |
| 副食店 | 启动时读取已安装模组档案的 `side_dish_shop` |

## 已知限制

- JEI 在 `/reload` 后是否立即刷新仍建议在真实客户端人工确认；创造栏和配方书已有刷新代码。
- “每村至多一座副食店”目前由 GameTest 覆盖，真实村庄生成仍建议抽样验证。
- 副食店数据包在启动时根据已安装模组 jar 内的 `profile.json` 决定是否加载；仅通过外部数据包新增 `side_dish_shop: true` 不会动态挂载结构包，需要重启且档案应随模组提供。
- 当前标准农田处理器以原版小麦为替换目标；未来地区若需要替换胡萝卜、马铃薯等其他基础作物，应新增自己的处理器数据，或扩展处理器的输入方块字段。
- `/reload` 会补上缺失交易并移除已失效交易；已有报价的精确价格更新仍以重新生成报价为准，避免频繁重置村民交易次数。
