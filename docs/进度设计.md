「三效合一」使用组合判据：`greasy_combo` 要求 `greasy + warmth + nourishing` 同时存在，
`refreshing_combo` 要求 `refreshing + warmth + nourishing` 同时存在；两组满足任意一组即可。
不能用三个任意效果分别解锁。两分支只把效果 ID 换成 CRCI 命名空间，判据语义与旧模组一致。

绝大多数判据是原版触发器，整条写在 `advancement/*.json` 里；只改文案 / 图标 / 图标物品不用碰代码：

| 进度 | 判据 | 触发器 |
| --- | --- | --- |
| 东北乐事 | `smelted` / `vat` | `recipe_crafted` / `inventory_changed` |
| 快乐老家 | `yard` | `location`（结构 `northeast_china_delight:northeast_yard`） |

## CRCI 公共器具的进度回调

大灶、脸盆架、大铁锅和谜之炖菜属于 CRCI，不能反向依赖东北乐事的 `ModAdvancements`。
CRCI 在 `util/CrciProgressHooks` 暴露 `Listener`，并提供 `onStove`、`onWashed`、`onMysteryStewServed`
三个默认空实现；东北乐事在 `advancement/NortheastProgressHooks` 注册自己的监听器后转成对应进度。
监听器使用可并存列表，未来其他地区乐事可以各自注册，不覆盖东北乐事。

谜之炖菜的挑战条件在煮好时计算并写入 `BigPotBlockEntity` 的持久字段
`ChallengeMysteryStew`：配方必须是 `chinese_regional_culinary_ingredients:mystery_stew`、
调料至少 3 种、实际效果至少 3 种。标记在盛出第一份时消费；盛出流程必须在 `give()` 前固定本次菜品判定，
再调用 `CrciProgressHooks.onMysteryStewServed`，未盛完、拆灶或换锅都不会重复发放。

「挨户串门」一条判据对一个院子模板：`northeast_china_delight:northeast_yard_garden` → `garden`
（去掉命名空间和 `northeast_yard_` 前缀，规则在 `ModAdvancements.yardCriterion`）。五种院子共用一个结构 id、
共用 `minecraft:location` 触发器，数据包分不出进的是哪一种，所以只能写代码。往
`NortheastCourtyardStructure.DEFAULT_TEMPLATES` 加新院子模板时，要在 `visit_all_yards.json` 的 `criteria` 里
补一条同名判据，并在 `requirements` 里按「一条判据一组」加上，否则进了那种院子不算数。
