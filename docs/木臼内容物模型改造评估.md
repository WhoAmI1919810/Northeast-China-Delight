# 木臼内容物模型改造评估

> 2026-10-27；仅评估，未改渲染代码。

## 现状

- `PoundingRecipes.Recipe.stageModels` 既决定阶段数量，也保存每阶段模型 ID。
- `STATE > 0` 时 blockstate 为 `RenderShape.INVISIBLE`，由 `WoodenMortarRenderer` 绘制阶段模型；`STATE == 0` 用静态空臼模型。
- `NortheastChinaDelight#registerAllBlockModels` 已登记全部 `models/block/*.json`，内容物模型放这里无需新增注册。
- JEI `PoundRecipeCategory#drawStation` 目前只画 `stageModels[0]`，改 overlay 后必须补画空臼底座。

## 推荐方案

新增可选字段 `"stage_model_mode": "full" | "overlay"`，默认 `full`：

- `full`：完全保持现有语义，旧数据包不受影响。
- `overlay`：`stage_models` 仍负责阶段数和顺序，但模型只含臼内内容物。
- overlay 时 BER 先画固定 `block/wooden_mortar`，再按同一 PoseStack 和朝向画内容物；缺模型时只画空臼，不能回退完整模型。
- `STATE == 0` 继续静态渲染；`STATE > 0` 继续 `INVISIBLE`，48 条 blockstate 不用改。
- 有料时 `MALLET` 已被清除，因此 overlay 底座固定为空臼，与带锤模型不冲突。

不建议直接把 `stage_models` 无条件改成内容物语义：旧数据包会显示“底座 + 完整木臼”的双层模型。

## 改动面与难度

| 位置 | 改动 |
|---|---|
| `PoundDataRecipe` | 解析模式，默认 `full` |
| `PoundingRecipes.Recipe` | 增加模式字段与访问器，更新重设 ID 的构造 |
| `WoodenMortarRenderer` | overlay 时叠画底座和内容物 |
| `PoundJeiRecipe(s)` / `PoundRecipeCategory` | 传递模式，JEI 改画两层 |
| `rice_cake.json` | 切换 overlay 并使用新模型 |
| GameTest / 回归测试 | 增加 full 缺省和 overlay 验证 |
| 1.20.1 独立树 | 同步代码与资源 |

代码约 70~120 行，难度低到中等；主要工作是双树同步、四朝向和 JEI 对齐。预计 2~4 小时。

## 风险与验收

- 内容物模型须使用方块 `0..16` 坐标，不能带物品模型 display transform。
- 当前使用 `RenderType.cutout()`；若内容物有半透明像素，需单独确认 translucent。
- 若新增内容物模型与底座有重叠面，需检查 z-fighting。
- 阶段列表数量仍决定 `STATE` 上限，不能只给成品一个模型。

验收：四朝向与 `STATE 0..5` 无紫黑、错位、缝隙、双层臼身；带锤空臼正常；JEI 站台与图标均为“空臼 + 内容物”；旧配方不写新字段时行为不变；1.20.1/1.21.1 一致。

## 结论

可以改，无需重写木臼玩法。推荐新增 `stage_model_mode` 保留兼容；若确定不再兼容旧数据包，也可直接改 `stage_models` 语义，但不建议在 3.x 小版本采用。
