# 1.20.1 适配计划（2026-10-08 决策）

> 背景：1.20.4 那条线做完之后发现一个硬伤 —— **机械动力（Create）官方从来没有 1.20.2~1.20.6 的版本**，
> 而本模组有一大块内容（黄铜碗 / 大盆两个容器、风干、47 个 create 配方）是靠 Create 撑起来的。
> 所以决定：**主目标改成 Minecraft 1.20.1**（Create / 农夫乐事 / JEI / Jade 在 1.20.1 上都是完整生态）。
> 1.20.4 这条线后来（2026-10-09）决定不再支持，节点与相关构建配置已从工程移除；那一轮的成果已并入 1.20.1 节点。

## 四、1.20.1 上要新做的工作

1. **构建节点**：`settings.gradle` 加 `1.20.1`；`versions/1.20.1/gradle.properties`；
   `build.gradle` 增加第三条分支（`<=1.20.1` 用 legacyforge，`<1.20.5` 用 NeoGradle，`>=1.20.5` 用 moddev）；
   `src/main/templates-legacy/META-INF/mods.toml` 复用；mixin 需要 refmap（1.20.1 Forge 生产环境是 SRG 名，
   MDG legacyforge 自带 `mixin { }` 扩展，Create 的写法可照抄）。
2. **命名空间迁移**（最大块）：源码里 **39 个文件、106 行** `net.neoforged.*` import。
   映射表：
   - `net.neoforged.bus.api.{IEventBus,SubscribeEvent}` → `net.minecraftforge.eventbus.api.*`
   - `net.neoforged.fml.common.{Mod,EventBusSubscriber}` → `net.minecraftforge.fml.common.*`
   - `net.neoforged.neoforge.registries.DeferredRegister` → `net.minecraftforge.registries.DeferredRegister`
   - `DeferredHolder / DeferredBlock / DeferredItem` → `RegistryObject`
   - `DeferredRegister.createBlocks/createItems` → `DeferredRegister.create(ForgeRegistries.BLOCKS/ITEMS, MODID)`
   - `DeferredRegister.Blocks.registerBlock(name, factory, props)` → `register(name, () -> ...)`（25 处左右）
   - `neoforge.common.loot.{IGlobalLootModifier,LootModifier}` → `net.minecraftforge.common.loot.*`
   - `neoforge.event.village.VillagerTradesEvent` → `net.minecraftforge.event.village.*`
   - `neoforge.gametest.{GameTestHolder,PrefixGameTestTemplate}` → `net.minecraftforge.gametest.*`（已实测存在）
   - `neoforge.client.extensions.common.*` / `client.model.data.ModelData` / `fluids.FluidType` / `items.ItemStackHandler` → `net.minecraftforge.*`
   - `NeoForge.EVENT_BUS` → `MinecraftForge.EVENT_BUS`；`NeoForgeRegistries` → `ForgeRegistries`
3. **事件总线**：NeoForge 20.x 的 `@Mod` 构造器注入 `IEventBus` → Forge 47.1 用
   `FMLJavaModLoadingContext.get().getModEventBus()`；`@EventBusSubscriber(modid=...)` 的注解包名与参数不同。
4. **数据包**：转换脚本加 `1.20.1` 模式 —— 不丢 create 配方与 `pump_seasoning` 进度；
   `forge:` 标签路径按 FD 1.20.1 核对（例如 1.20.1 的通用标签可能是 `forge:raw_fish` 而不是 1.20.4 的 `forge:raw_fishes`，
   这一条要用 FD 1.20.1 的 jar 实查后再定）。
5. **Create 联动回归**：`compat/create/**`、风干 JEI 分类、47 个 `create:` 配方全部恢复；
   代码要对 1.20.1 的 Create 6.0 API（`AllFanProcessingTypes` / `FanProcessingType` / `CreateBuiltInRegistries`，
   `<本地工作目录>` 下已经有一批反编译出来的类可供参考）重新分支。
6. **JEI 15 / Jade 11**：分类 API 与 1.21.1 的 JEI 19 / Jade 15 不同，`GrillRecipeCategory` / `VatRecipeCategory`
   与 Jade provider 要再加一层版本分支。
7. **实机验收**：`:1.20.1:runServer`（0 error）→ `:1.20.1:runClient`（渲染 / JEI / Jade）→ 出包。

## 五、决策（2026-10-09 定案）

1. **只做 1.20.1**：1.20.4 那条线到此冻结 ——
   根因是 Create 官方没有 1.20.2~1.20.6 的任何版本，而本模组的黄铜碗 / 大盆 / 风干 / 47 个 create 配方都依赖它，
   1.20.4 上再怎么补也补不齐内容。
2. **1.20.4 节点已移除**（2026-10-09 决定）：工程只剩 1.20.1 与 1.21.1 两个节点，
   版本差异仍用 `//?` 条件注释锚定，1.21.1 是主线。
3. **1.21.1 与 1.20.1 的联动代码接受版本分支**：1.21.1 用 Create 6.0.10（1.21 版）、1.20.1 用 Create 6.0.8，
   API 不完全一样，按版本分支写。
