# 批量风干配方数据包用法

最后更新：2026-10-13，模组版本 3.0.0。

## 路径与默认规则

此配方属于服务端数据包，不是客户端资源包。类型为 `northeast_china_delight:drying`，默认 ID 为 `northeast_china_delight:drying/dried_tofu`。

- 1.21.1：`data/northeast_china_delight/recipe/drying/dried_tofu.json`。
- 1.20.1：`data/northeast_china_delight/recipes/drying/dried_tofu.json`。

```json
{
  "type": "northeast_china_delight:drying",
  "config": {
    "priority": 0,
    "input": {"tag": "c:foods/soy_milk"},
    "results": [
      {"item": "northeast_china_delight:dried_tofu", "count": 1},
      {"item": "minecraft:bowl", "count": 1}
    ]
  }
}
```

1.20.1 使用 `forge:foods/soy_milk` 标签。默认仍接受既有豆浆标签中的候选，每份原料得到一个干豆腐及一个空碗；多份输入按数量扩大两个产物并按物品堆叠上限拆分。

## 字段

| 字段 | 说明 |
| --- | --- |
| `config.disabled` | 可选，默认 false；true 时其余加工字段可省略，停用该 ID。 |
| `config.priority` | 可选，默认 0，32 位整数；从高到低选择，同值按 ID 字符串排序。 |
| `config.input` | 必填 Ingredient，支持 `item`、`tag`、任选数组及平台支持的自定义原料。 |
| `config.results` | 必填数组，1–2 个产物；每项有 `item` 和可选 `count`，默认 1。 |

成品物品必须已注册，数量是正整数且不得超过该物品的堆叠上限。配方不配置秒数：风干进度与整堆物品的时间倍率由 Create 的 `fanProcessingTime` 控制，保持机械动力原有处理方式。

## 覆盖、停用与新增

同路径覆盖原 JSON 即可改变干豆腐规则。停用示例：

```json
{"type":"northeast_china_delight:drying","config":{"disabled":true}}
```

新增配方使用新 ID，例如 1.21.1 的 `data/example/recipe/drying/sweet_carrot.json`，将 `input` 改为胡萝卜，`results` 改为所需成品。两种候选不要拆成两个 ID，直接在 `input` 写任选数组即可。

执行 `/reload` 后 RecipeManager 重新加载规则，鼓风机查当前规则而不是 Java 固定清单。1.21.1 JEI 同步更新：一条规则一页，候选在输入格轮换，最多两个产物格，并暴露配方 ID。1.20.1 本轮同步了加工与数据包支持，保持既有 JEI 风干分类停用的状态。

Create 自己维护掉落物或传送带的处理进度缓存；对于已被判定不能加工的架上物品，调整配方后可先移出再投入气流。裸风类型仍只在鼓风机紧邻的空气格成立，不改变水、熔岩、火焰等其他鼓风机处理类型。
