# 大缸配方数据包用法

大缸使用 `northeast_china_delight:vat` 配方类型，默认 15 条规则位于 `data/northeast_china_delight/recipe/vat/`。每个文件的资源路径就是稳定 ID，例如 `vat/pickle.json` 对应 `northeast_china_delight:vat/pickle`。1.20.1 打包后目录由降级脚本改为 `data/northeast_china_delight/recipes/vat/`，ID 不变。

## 覆盖与禁用

数据包按相同命名空间和路径放置文件，即可覆盖本模组内置配方。在 1.21.1 使用 `data/northeast_china_delight/recipe/vat/bean_sprouts.json`，在 1.20.1 使用 `data/northeast_china_delight/recipes/vat/bean_sprouts.json`。例如禁用豆芽：

```json
{
  "type": "northeast_china_delight:vat",
  "config": { "disabled": true }
}
```

修改配方时复制原 JSON 到数据包相同路径，再编辑 `config`。例如豆芽将 `seconds` 改为 `60`（秒）。`priority` 决定多个候选规则同时匹配时的优先顺序；`slots[].ingredient` 可指定 `item`、`tag` 或已有的 `matcher`，也可以用数组表示“任选一种”。数据包新增别的路径即可创建新 ID。

`kind` 是历史遗留的枚举，只能填已有的那十几个名字（`PICKLE`、`PASTE`、`KVASS` 等），填别的加载直接失败。它现在基本只是个标记：缸靠配方 ID 而不是 kind 判断自己在跑哪条。新配方借用任意一个已有 kind 即可，产物、原料、时长都不受它影响。唯一的副作用是旧存档里那些只记了 kind、没记配方 ID 的缸，会在同 kind 的配方里挑 `priority` 最高的那条认领，所以日志里会警告「一个 kind 被多条配方使用」。不要指望改 kind 来改变加工行为。

1.21.1 的通用物品标签使用 `c:`；1.20.1 数据包需按 Forge 命名空间使用 `forge:`（本模组自带 JSON 构建时自动转换）。本模组会随配方同步重新生成大缸 JEI 页面。禁用现有配方后，已酿成的缸仍可提取记录的液体；已绑定但尚未完成且配方已消失的缸，即使进度仍为零，也不会再接受新原料、封口或继续发酵，空手右键可返还未加工的原料。没有 ID 的旧存档按既有 `kind` 回退。

普通合成、厨锅和 Create 配方也已分别按游戏原生 JSON 路径支持数据包覆盖；2026-10-13 已将烤架的四条默认配方迁入数据包，烤架用法见 `docs/烤架配方数据包用法.md`。

不写 `liquid` 就是无液体配方。当前内置辣白菜即为此例：它不要求清水、不产出酸引水，也不声明取液容器，成品只能空手取出。无液体时 `bounds` 应使用固定值（`exact` / `between`），不要再用 `per_layer`、`min_by_water` 或 `seconds_per_layer`；后三者会按水位 0 兜底成单层，数据包作者很难看出实际数量。需要让调料随主料增减时可用 `half_of`：辣白菜主料为 1–6 棵，盐跟随第 0 格（`{"type":"half_of","slot":0,"max":3}`），4 棵需要 2 份盐、6 棵需要 3 份盐；1 棵仍只需 1 份。

## 工序动词

`config.verb` 是可选字段，右键进度提示、Jade 进度条和 JEI 时长共用这一动词。内置配方已明确使用发芽、发酵、腌制、酿造或冷冻；旧数据包不写 `verb` 时，按原有 `kind` 使用对应默认动词，不影响原料、时长、产物或旧存档。

在原有 `config` 中增加字段即可，不要用下面的片段替换整份配方：

```json
{ "verb": "催芽" }
```

也支持文字对象 `{ "verb": { "text": "催芽" } }`，或翻译键 `{ "verb": { "translate": "example.process.sprouting" } }`。翻译键需在客户端资源包的语言文件中定义；只提供服务端数据包时，直接写文字最方便。字段随服务端配方同步，改 ID 或重载后仍保留。动词不能留空，`text` 与 `translate` 不能同时填写。

动词只是一个词，真正显示出来的是把它嵌进句式之后的整句。默认句式是写死的中文语序（「腌制中 50%」「腌制进度 50%，还剩 1 分 20 秒」），别的语言或别的说法会拼不对。所以每处显示都可以在配方里换整句的翻译键，不写就用默认的：

| 字段 | 显示位置 | 默认翻译键 | 占位符 |
| --- | --- | --- | --- |
| `progress` | Jade 进度条，进行中 | `jade.northeast_china_delight.vat.progress.custom` | 动词、百分比 |
| `done` | Jade 进度条，完成 | `jade.northeast_china_delight.vat.done.custom` | 动词 |
| `time` | JEI 的时长 | `jei.northeast_china_delight.vat.process_time` | 动词、时长 |
| `hint.long` | 游戏内动作条，剩余超过一分钟 | `message.northeast_china_delight.vat.progress.hint` | 动词、百分比、分、秒 |
| `hint.short` | 游戏内动作条，剩余不到一分钟 | `message.northeast_china_delight.vat.progress.hint_seconds` | 动词、百分比、秒 |

`hint` 的两个键必须一起给。值写成字符串或 `{ "translate": "..." }` 都行：

```json
{
  "progress": "example.vat.progress",
  "done": "example.vat.done",
  "hint": { "long": "example.vat.hint.long", "short": "example.vat.hint.short" }
}
```

翻译键要在语言文件里定义，占位符顺序和默认句式一致，第一个永远是工序动词。

## 产物液体

`liquid.product` 写流体 ID，例如 `"northeast_china_delight:soy_sauce"` 或 `"create:tea"`，配合 `product_mb` 指定总量。总量上限是缸的实际容量 `3000 mB`（3 层）；`product_per_layer` 为真时按水位层数倍增，倍增后的总量同样不能超过 `3000 mB`。发酵完成后的液面直接使用该流体自己注册的静止贴图和颜色，不需要为新液体准备方块模型。

旧数据包里写的枚举名（`PASTE`、`SOY_SAUCE`、`VINEGAR`、`WHITE_VINEGAR`、`FISH_SAUCE`、`SHRIMP_PASTE`、`KVASS`、`SOUR_WATER`）仍然能用：没有冒号的值按这张旧名单翻译成对应流体。带冒号的值一律当作流体 ID 去注册表查找。清水不能作为产物。

## 装瓶

`liquid.serving_container` 和 `liquid.serving_item` 必须成对出现，指定「拿着什么容器来取」和「取出来变成什么」。每取一次扣 `250 mB`。例如把茶装进玻璃瓶：

```json
"liquid": {
  "product": "create:tea",
  "product_mb": 3000,
  "serving_container": "minecraft:glass_bottle",
  "serving_item": "create:builders_tea"
}
```

只写其中一个会在加载时报错。两个都不写时按流体给默认装法：大酱用碗盛出大酱，酱油、醋、白醋、鱼露、虾酱、格瓦斯、酸引水用玻璃瓶；除此之外的流体没有默认容器，只能用泵抽走。

JEI 的「取货容器」格显示的就是这个容器，它不是发酵原料，不参与原料搜索。

## 成品与取货

| 配方定义 | 取货方式 |
| --- | --- |
| `slots[].fate=KEEP` 或 `CONVERT` 的固体成品 | 完成并移除封口物后，空手右键逐份取出；例如豆芽、酸玉米粒、酸菜、腌雪里蕻、酱渣。 |
| `slots[].fate=ABSORB` | 发酵完成时就消耗掉。和 `CONSUME` 的区别只在于可以写 `refund`：消耗的同时返还一个容器（辣椒酱还一个碗）。没有 `refund` 的，比如盐和树叶，完成时直接消失。 |
| `slots[].fate=CONSUME` | 发酵完成时消耗掉，不返还任何东西。 |
| 写了 `serving_container` 的液体产物 | 拿着该容器右键，每份 `250 mB`，得到 `serving_item`。 |
| 没写装瓶字段的液体产物 | 见上面的默认装法；没有默认容器的流体只能泵抽。 |
| 同时有固体与液体产物 | 空手取固体、持容器取液体，各自保留另一类产物；不必先把液体取空才能拿固体。 |

成品取完后才清空缸的加工状态。制作完成后普通空手右键走移除封口物和取货，不再拦截为“已酿好”的进度查询；未完成时仍可查询进度。普通 `vat/pickle` 的输入映射包含雪里蕻，产出腌雪里蕻；它和酸菜、酸黄瓜、腌胡萝卜、腌青萝卜同属大缸腌制进度组。农夫乐事的卷心菜不等于本模组大白菜，原有酸菜原料限制保持不变。

JEI 产物格显示缸中实际成品，另设“取货容器”展示格；容器不是发酵阶段的原料，不参与原料搜索。固体成品会注明可空手取出。格瓦斯显示为 `1500 mB` 格瓦斯液体，玻璃瓶仅作为取货容器显示，装瓶后的饮品不是大缸直接生成的产物。

## 取货时的换算（converter）

`fate=KEEP` 的槽位可以在取出时把原料换成成品。`converter` 现在支持两种写法：

- 旧字符串：`"pickle"`、`"spicy_pickle"`，保留用于兼容旧数据包。
- 映射对象：`type: "mapped"` + `entries`，按数组顺序取第一个匹配条目，未命中的原料原样返还。

```json
"converter": {
  "type": "mapped",
  "entries": [
    {
      "ingredient": { "tag": "c:crops/napa_cabbage" },
      "result": "northeast_china_delight:spicy_cabbage"
    }
  ]
}
```

`entries[].ingredient` 与普通槽位一样支持 `item`、`tag`、`matcher`。例如辣白菜配方的主料槽使用 `northeast_china_delight:spicy_pickle_ingredients`（当前只有 `#c:crops/napa_cabbage`），再由映射决定大白菜取出为辣白菜。以后新增辣萝卜、辣黄瓜等同族配方时，只需扩主料标签并补一条“原料 → 成品”映射；不同产物会让 JEI 按产物拆页。1.20.1 数据包中的 `c:` 标签按既有规则写成 `forge:`。

## 完成后留缸续做

不新增工序链字段，也不把某两道工序写死。缸完成并取下封口物之后，能不能接着备下一道，只看现存内容能否被另一条未禁用配方接住。当前这条配方不会把自己当成下一道。

| 操作 | 规则 |
| --- | --- |
| 成品液体还在 | 不能加水，也不能投入下一道原料。先用对应容器把这种液体取尽。 |
| 加水 | 另一条配方还要更多清水，且缸里每一份固体都能被它当作原料、数量不超上限时，水桶才倒得进去。酸引水和清水仍然不能混。 |
| 加固体或封口 | 手里的东西必须是某条可续配方的合法原料或封口物。材料、液体和封口都齐了，才清除“已完成”和进度，改绑新配方并开始计时。没齐时，原来的完成状态和剩料都留着。 |
| 空手 | 仍逐份取出固体成品。 |
| 拿错东西 | 这一下被吃掉，不会因此取走酱渣或其他剩料。 |

`CONVERT` 完成后按缸里的实际物品匹配。酱油或大酱留下的酱渣，就可以直接当作醋配方里的酱渣，再加水、加谷物、盖粗布毯。`KEEP` 在判断续做时不会按 `converter` 自动换成取出来的样子；下一道必须直接接受缸里现在的物品。自定义配方只要槽位、液体和封口对得上，就走同一套规则。

缸里只剩酸引水时，声明了酸引水的下一道也能接住，例如泡菜取走蔬菜后加谷物、盖粗布毯做白醋。这种缸不能再倒清水。

## 数据包与资源包的区别及扩展范围

2026-10-13 核对：配方属于服务端数据，应通过数据包的 `data/` 目录加载；普通客户端资源包的 `assets/` 目录用于贴图、模型等资源，不能通过客户端资源包列表覆盖服务器配方。单人游戏也需要把配方作为当前世界的数据包加载。

| 加工类型 | 当前状态 |
| --- | --- |
| 大缸 | 两版已支持稳定配方 ID、JSON 覆盖、新增及 `config.disabled=true` 禁用；产物液体可写任意已注册流体，装瓶容器和成品物品由配方指定。`kind` 仍只能用既有枚举名。 |
| 烤架 | 两版已注册 `northeast_china_delight:grill`，四条默认配方由 RecipeManager 加载；支持新增、覆盖、禁用、调料份数、产物数量及烤制时长，JEI 随服务端配方更新。 |
| 普通合成、熔炉、厨锅、Create | 已有对应 JSON 配方，使用各自的配方类型和资源路径由数据包覆盖。 |

烤架的配方 ID 会记录到每个食材槽位，重载时读取同 ID 的新规则并重新计时；禁用或删除后停止加工且保留原料，不会串到其他同食材配方。旧存档无 ID 时才按输入和优先级回退，重复或重叠调料条目逐份匹配。实现入口、默认 JSON 和回归用例见项目结构索引。
