# 唱片「大东北我的家乡」与歌词 HUD

> 最后更新：2026-10-16（结论：歌词 HUD 是纯显示层，歌曲"唱到最后几句被切断"来自 ogg 素材本身只有 1:56.30；同日唱片换成自己的 16×16 贴图，并给东北小院加了保底出唱片的箱子，见 `项目结构与资源索引.md` §6）

## 2. 停止时机由谁决定

- 唯一停止逻辑是原版 `JukeboxSong.hasFinished(ticks)`：`ticks >= ceil(length_in_seconds × 20) + 20`（`SONG_END_PADDING_TICKS = 20`）。
- 本曲 `length_in_seconds = 116.3` → `lengthInTicks = 2326` → 第 **2346 tick（117.3 秒）** 服务端才会停止曲目；音频实际只有 **116.299 秒**，即唱片进度比音频晚 1 秒结束。
- 全模组没有 `stopSound`/`SoundManager.stop()` 调用，`LyricsHudOverlay` 与 `SoundEngineMixin` 都只读取状态，不存在代码提前掐断。

## 3. 素材核查（2026-10-16）

逐包解析 + jorbis 解码（工具见 §5）。一句话结论：**素材本身是被剪过的一版，歌曲在 1:54.1 处乐器齐停、只剩混响余音，代码没有提前停曲。**

**容器层**：44.1 kHz / 2ch / 438 页，无空洞、无解码错误，解码总长 **116.2988 秒**（granule 5128778），vendor `Xiph.Org libVorbis I 20150105`，注释 `ENCODER=FL Studio`。它、`临时素材/大东北.ogg`、已构建 jar 内的副本，三者哈希一致（`D232145C…0342F8`）。

**结尾（20 毫秒窗，最关键的证据）**：

| 时间 | 现象 |
| --- | --- |
| ≤ 1:54.13 | 满编制，鼓点峰值 0.7–0.86，与全曲副歌同级 |
| 1:54.14 起 | 鼓与打击乐的瞬态**立刻消失**，只剩一条平滑的音调余音 |
| 1:54.6 / 1:55.3 / 1:56.0 | 依次 -29 / -38.9 / -46.7 dB |
| 1:56.27（最后一个样本） | -50.8 dB（rms 0.0029，**始终没有归零**） |

余音以约 12.5 dB/s 稳定衰减到听不见为止——即"乐器齐停 + 混响余音"，而不是"波形被咔嚓切平"。0.5 秒窗看得更直观：1:53.5 仍 -17 dB，1:54.1 → -24，1:54.6 → -33，1:55.1 → -39，1:55.6 → -45。

**段落分界**：全曲几乎单声道（L/R 相关系数 ≈ 1.00），只有 7 处短暂变宽：**15.3 / 32.2 / 47.3 / 64.4 / 79.3 / 95.9 / 112.9 秒**，间隔 14.9–17.1 秒，形如每 8 小节的段落线。也就是说 1:52.9 刚进入一个新段落，**1.2 秒后就被剪掉了**。

**开头**：0–1.41 秒是渐强引入（-57 → -29 dB），紧接着 **1.43–1.87 秒是 0.45 秒的数字绝对静音**（rms 恰为 0.00000），1.87 秒满音量直接进入。原始录音不会出现零点几秒的绝对静音，说明这份素材经过剪辑/拼接。

**歌词与素材是对齐的**：末句 1:32.0 落在第 4 个段落（79.3–95.9）里，之后 95.9、112.9 两个段落没有对应歌词——16 句歌词刚好填满前 4 段。于是从 1:32 到 1:54.1 一直挂着最后一句歌词、音乐还在走，到 1:54.1 音乐被剪掉：听感正是"唱到最后一句突然中断"。

对照网络检索到的该曲常见录音时长（约 3:47–4:14，仅供参考），本素材约为其一半。

结论：**不是代码把歌停了，是素材只有 1:56.30 且结尾被剪**。原版停止逻辑要到第 2346 tick（117.3 秒）才触发（§2），比音频结束还晚 1 秒；模组内没有任何 `stopSound`。要么接受这份素材，要么换一份完整录音（同步点见 §4）。
## 4. 换音频时必须同步的地方

1. `data/northeast_china_delight/jukebox_song/northeast.json` 的 `length_in_seconds`（建议按实际时长减 0，游戏会自己多留 1 秒）。
2. `client/LyricsHudOverlay.java` 的 `SONG_LENGTH`（当前是硬编码，与上面重复；换成完整音频后建议顺手改为从 `JukeboxSong` 注册表读取，避免两处不同步）。
3. 若新音频更长，需要补 `LYRICS` 时间轴与 `lang/*.json` 中 `lyrics.northeast_china_delight.*` 的条目。

## 5. 复核工具（不在工程内）

`E:\codex\basin_models_work\audio\`

- `ogginfo.py`：纯 Python 解析 ogg 页/granule，给总时长、页数、串号，并报告"最后一页之后是否还有多余字节"。**先跑它**。
- `oggdur.py` / `oggseq.py` / `oggcomments.py` / `oggcheck.py`：早先写的 ogg 解析与注释查看脚本。
- `RmsDec.java`：jorbis 解码 + 0.5 秒窗 RMS 包络（可传起始秒），判断"结尾是不是被截断"。
- `Fine.java`：同上的可调窗口版本（默认 20 毫秒），**用来看鼓点瞬态在哪一刻消失**，这是区分"自然收尾"和"剪切"的关键。
- `MsRatio.java`：mid/side 与 L/R 相关系数，用"立体声突然变宽"标记段落分界，进而判断结尾切在段落中间。
- `Scan.java`：整文件解码体检（页数/包数/空洞/损坏）。
