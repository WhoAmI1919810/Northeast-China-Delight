## 二、边界细则

### 中国烹饪食材

**食材和收纳**
- 食材本体约 93 样：生食材 20、种子和菌种 13、肉和下水 15、海鲜 5、腌菜冻货 9、豆制品粉面等 17、调料 14。
- 作物植株和野生植物方块 23 个。
- 菜筐 19、麻袋 9，以及它们的装拆配方、从作物取种子的配方。

**调料和原料链**
- 13 种流体，以及调料瓶那一套：瓶子留在农夫乐事厨锅里按 50 mB 扣的 mixin、机械动力灌装倒出。
- 大缸的 6 种调料配方：酱油、大酱、醋、白醋、鱼露、虾酱。
- 原料链：大酱块、酱渣、一种通用制盐方法。

**机器和厨具**
- 方块、方块实体、渲染、配方类型、JEI 页、Jade 一起进前置。
- 大缸：配方引擎改成别的模组能注册自己的种类（见第四节）。
- 木臼：舂捣。
- 烤架：烤架营火、烤串的调料。
- 大锅大灶：大锅烹饪、锅里的显示、锅盖。
- 大脸盆、水盆、黄铜碗。
- 盆装菜放下来的那套方块规则：盛 4 碗、盛完剩空盆。
- 机器里食材的显示模型，包括大缸里、锅里的。菜在锅里的模型跟着菜走，留在各乐事里；前置按菜的命名空间去找。

**风干：** 配方类型、机械动力鼓风机的风干加工、JEI 页。干豆腐那条配方留在东北风土乐事。

**菜放成方块的那套：** 菜肴方块的各种方块类，以及盘子、碗、托盘的模型模板。具体的菜留在各乐事，用前置的这套注册。

**谜之炖菜：** 规则、22 类食材分类和珍稀度的标签、盆装谜之炖菜。

**口味效果**
- 油腻、爽口、暖身、养生四个效果，以及它们的机制：少掉饥饿、饱时回血、冷的地方走得快、按血量回血，还有「食用后获得：」的提示。
- 「哪道菜给什么口味」现在是东北乐事里写死的一张表，要改成数据，由各乐事自己写。

**其它：** 「去处」和启用列表（第三节）；`c:` 通用标签；DdIds、DdStacks 这类两个版本的适配工具类。

**村庄副食店和副食商（2026-11-11 用户定）**
- CRCI 提供：副食店结构模板与通用生成框架、原版村庄 houses 池的统一注入、副食商职业与工作方块、「副食店生成档案」接口，以及副食商交易池的合并与过滤。
- 各乐事通过生成档案决定：是否生成副食店和副食商；在哪些村庄 / 群系生成、权重和数量；箱内战利品。
- 各乐事另外注册副食商交易项，包括卖什么、等级、价格与补货。副食商不绑定某个地区的店铺档案：所有已安装且已启用乐事的交易项合并成一个交易池，可以混着卖各地区的东西。
- 五个群系的 `village/relish_*`、houses 池覆盖逻辑和生成框架统一由 CRCI 管，避免多个乐事互相顶掉；CRCI 不能反向依赖东北乐事，拆分时结构内的东北建材依赖另行处理。
- 未安装的乐事不会加载它的生成档案、启用列表或交易项，因此它启用的 CRCI 内容不会进入副食商交易池。对应物品即使已经在 CRCI 注册，也按未激活处理：创造栏、JEI、配方、战利品、交易和世界生成里都不可见，只能通过 `/give` 等指令取得。
- CRCI 不默认启用任何乐事的副食店；没有乐事启用生成档案时，不生成副食店，也不生成副食商。
- 现有东北副食店 NBT 和结构资产迁入 CRCI；东北乐事只提供生成档案和交易项。旧东北乐事分支保持现状，只修 bug。

### 东北风土乐事

- **加工配方：**
  - 厨锅、烟熏炉、砧板、机械动力做食材的配方（调料原料链除外）；
  - 大缸里的 9 种：腌菜、辣白菜、咸腊肉、咸鱼、豆芽、酸玉米、格瓦斯、冻梨、冻豆腐；
  - 舂捣 3 条、烤架的烤串配方、风干的干豆腐、水盆煮盐。

- **启用列表**，以及只属于东北的去处，比如东北小院箱子里放什么。

## 三、启用列表和「去处」

**做法：** 前置里写好每样东西的默认去处，各乐事用启用列表打开。

### 启用列表

- 每个乐事在自己的数据里列出要启用的前置物品，写成前置的一个物品标签「已启用」；副食商交易项也属于这份乐事数据。各乐事都往里加，装几个就取并集。
  一样样列，或者引用一个分组都行。整合包作者能用数据包增删。
- 游戏读到这个列表以后：
  1. **显示：** 前置的创造模式物品栏只放已启用的，创造模式搜索也就搜不到别的；JEI 运行时把没启用的藏掉；
     大缸、木臼、烤架、大锅烹饪这些 JEI 页只列产物已启用的配方。
  2. **生成：** 前置写好的默认去处，只有已启用的东西才生效。
- 没启用的东西仍然注册，因为注册表要在所有模组之间一致；只是看不见、不生成。`/give` 照样能给。
- 未安装的乐事没有数据加入「已启用」并集，因此它独有的内容等同于未启用。比如西南乐事没安装时，CRCI 里即使注册了干辣椒，也不会出现在创造栏、JEI、交易或任何生成里；安装了西南乐事之后才会进入可用内容与副食商交易池。
- 每个启用项和副食商交易项都记录所属乐事或内容源；CRCI 只接受对应乐事已安装的条目。数据包增删也走同一归属校验，不能绕过这一限制。

### 前置提供的「去处」

| 去处 | 前置提供 | 怎么只对已启用的东西生效 |
|---|---|---|
| 村庄农田 | 统一覆盖原版 5 个农田文件，每种村庄能种哪些作物写在前置的数据里 | 摆农田时只从已启用的作物里挑 |
| 副食商交易 | 各乐事提供交易项，CRCI 合并成全局交易池 | 补货、升级时只取已安装且已启用乐事的交易项，可混卖 |
| 箱子战利品 | 往原版村庄、结构箱子里加什么、多少，写成数据 | 开箱时判断 |
| 野生植物 | 人参、榛子丛、榛蘑、野生木耳、桔梗，长在什么群系、多密，写成数据 | 地物生成时判断 |
| 钓鱼、宰猪 | 按水域出带鱼、生蚝、海参、大虾；用刀宰猪掉下水 | 掉落时判断 |

- 新的乐事只要把用到的东西写进启用列表，人参就会照前置写好的规则在世界里长、进箱子、进交易，不用写代码。
- 乐事自己的特色去处，比如东北小院箱子，写在乐事自己的数据里，用前置的物品。
- 好几个乐事都启用同一样东西时，只按前置那一份规则生成，不会翻倍。
- 原版农田文件只由前置覆盖，不会互相顶掉。

**详细实施评估（2026-11-11）：** 见 `docs/区域作物启用与售卖实施评估.md`。结论是把「归属」「启用」「投放」拆成三层：所有食材统一注册在 CRCI，由各地区的可并集 `enabled_content` 启用；菜肴、建材、结构等专属内容只能由所属地区启用。地区档案再用 `farm_crops` 和交易覆盖/注入决定具体生成和售卖。农田改为 CRCI 的单一加权池处理器，交易改为全局池加运行时守卫；配置只控制获取途径，不控制 CRCI 物品合成。默认交易池覆盖农民、流浪商人、副食商、屠夫、渔夫五类职业。按完整可见性估算约 14~20 个工作日；只做作物生成和五类职业售卖约 9~12 天。

**现状：** 这些都写死在东北乐事的 Java 里：野生地物 5 个、战利品修改器 7 个，农民、屠夫、渔夫、流浪商人的交易，以及配置里的村庄作物名单。
搬进前置时要改成「数据 + 只认已启用的东西」。副食商已确定随副食店进前置；生成条件由各乐事的副食店档案提供，交易项汇总所有已安装且已启用的乐事，不按店铺地域隔离。

**大缸通用化为什么费事：** 大缸约 5000 行，配方数据里引用的东西都写死在 Java 里：

- 要认的流体。

要改成种类可由别的模组注册、匹配器换成标签、转换表换成数据。木臼、烤架、风干的配方已经是数据，搬起来省事得多。

## 五、难点

1. **大缸通用化和「去处」数据驱动**是两大块技术活。数据格式发出去以后不能随便改，设计时就要想好别的地区要配什么。
2. **三条产品线并行：** 旧东北乐事、新东北乐事分支、CRCI；每条线仍要维持 1.21.1 / 1.20.1 适配。
   - 旧线修的 bug，新分支和 CRCI 里多半也有，要几边一起改；
   - 4.0.0 发布前加的东西，分叉时一起带过去。
3. **前置的接口要稳：** 物品 id、标签名、启用列表的写法、各机器的配方格式、「去处」数据格式、口味数据格式、给别的乐事用的注册接口。第一版宁可少放。
4. **编译在用户那边：** 我这边不编译，第一次编 CRCI 新工程和东北乐事新分支肯定会冒出一批错误，要你贴报错回来，一轮轮修。
